### F6. 도구 51개 중 34개에서 입력 필드가 라벨과 프로그램적으로 연결되지 않음
- `net-salary`, `sleep-calculator`에서 처음 발견한 것을 계기로 51개 도구 파일 전체를 코드로 스캔한 결과, 34개 파일·74개 필드가 `<label>`은 있지만 `htmlFor`/`id` 연결이 없는 동일한 패턴으로 확인됨(CONFIRMED, 브라우저 devtools의 "No label associated with a form field" issue로 재현).
- 자동화 스크립트로 34개 파일에 `htmlFor`/`id`를 추가했다. **1차 스크립트는 정규식 backtracking 버그로 일부 라벨을 엉뚱한 입력 필드와 잘못 연결시키고(`BaseConverter.tsx`에서 확인) self-closing 태그의 `>`를 삭제하는 구문 오류(`Base64Encoder`, `JsonFormatter`, `UriEncoder`)를 만들었다 — 브라우저 재검증 중 스스로 발견해 전량 되돌리고 안전한 방식(문자열 재구성 없이 순수 삽입)으로 재작성했다.** 재작성 후 `.map()` 반복 렌더링에서 고정 id를 그대로 쓰던 3개 파일(`BodyFatCalculator`, `CalorieCalculator`, `MarginCalculator`)의 "Duplicate form field id" 버그를 추가로 발견해 배열 인덱스 기반 동적 id로 수정했다.
- 34개 파일 전부와 미변경 확인용 대조 파일들까지 dev 서버+브라우저로 재검증(콘솔 파싱 에러 없음, 중복 id 없음).
- 남은 것: 실제 입력 요소가 없는 orphan 라벨(버튼 그룹 헤딩), 라벨 자체가 없는 소수 필드, `<div>`로 감싸인 라벨-입력 쌍 2건, `<textarea>` 2건은 이번 자동 수정의 안전한 매칭 범위를 벗어나 있어 손대지 않았다 — `tasks.md` T8b에 파일명까지 정확히 남겼다.
